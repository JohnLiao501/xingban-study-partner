## 1. 测试原则

- 会话调度使用可注入时钟和随机种子，测试不等待真实分钟。
- AI、前台探针、截图、数据库和媒体播放器均通过接口替身隔离。
- 隐私失败按产品失败处理，不以“功能仍能运行”为通过理由。
- 所有测试使用无版权示例伙伴，不把白厄素材放入仓库或 CI。

## 2. 文档一致性

自动或人工检查以下内容在全部文档、Schema 和示例中一致：

- 十个 `ReactionKey` 名称与数量。

## 3. 单元测试

### 3.1 会话状态机

- 合法路径可以到达 completed、aborted、interrupted。
- 非法跳转返回 `SESSION_INVALID_TRANSITION`，数据库不改变。
- 暂停与休息不累计有效专注，不触发巡查。
- 异常中断不生成评价和信赖。

### 3.2 巡查调度

- 首次、正常、奖励和收紧间隔均在规定区间。
- 开始 2 分钟内、最后 60 秒、暂停和休息期间不巡查。
- 相同种子得到相同计划，不同种子没有固定可见模式。

### 3.3 判断与偏航

- 允许规则返回 focused。
- 禁止规则按真实采样时间在 0/5/10/15 秒均不确认，20 秒确认；重复调用巡查函数不能代替连续样本。
- uncertain 永不消耗额度。
- 两次 AI distracted 未达到阈值或相互矛盾时不处罚。
- 默认私人通讯即使被模型高置信判为 distracted 也只提醒；严格模式仍需两帧确认。
- AI 标签/原因码矛盾或伪造本地原因码时降级为 `uncertain / invalid_response`。
- AI 二次请求飞行期间停止共享、切换应用、暂停或销毁后，迟到结果不得处罚。
- 第三次偏航后会话继续且评价最高为 C。

### 3.4 评价与信赖

- S/A/B/C/D 边界值正确。
- 1、2、3 次偏航分别应用 A、B、C 上限。
- 信赖按公式计算且不为负。
- 不同 `partnerId` 的进度互不影响。

## 5. 集成测试

- 用户不选择屏幕时默认不共享，会话仍可仅用本地规则启动。
- 会话开始页默认选择私人通讯温和提醒，并允许用户逐场切换严格模式。
- 打开会话设置不会自动枚举屏幕；只有用户点击“加载可用屏幕”，或活动会话中点击“重新授权屏幕”，才调用系统捕获源接口。
- Electron 桌面巡查阶段不显示手工 `focused/uncertain/distracted` 按钮，避免与主进程自动结果竞态；浏览器预览仍保留模拟控件。
- 选择的 source ID 已失效时，捕获进入 failed 且会话安全继续。
- 捕获流被系统停止后广播状态并降级到本地规则。
- 前台探针退出后自动重启一次；再次失败后进入明确降级状态。
- API 超时、429、5xx、无效 JSON 和未知枚举均产生 uncertain。
- 远程 HTTP、URL 凭据/查询/片段、3xx、Markdown 包裹、额外字段和超过 64 KiB 的响应被拒绝。
- 主窗口不能调用截图窗内部 IPC，截图窗不能调用设置、伙伴或会话 IPC。
- 数据库迁移在事务中完成，失败时回滚。
- 主窗口关闭到托盘后会话继续；从托盘可停止巡查和退出。
- 巡查窗启用内容保护后不出现在应用自己的单帧中。

## 6. 媒体 QA

每个伙伴场景检查：

- 十类动作均有可播放候选。
- 视频为 H.264 MP4、1920×1080、24 fps、`yuv420p`。
- `idle_loop` 首尾无明显跳变；普通动作在约定时长内。
- 视频没有烧录字幕、水印、身份漂移、明显手部错误或场景突变。
- 音频为 OGG/Opus，字幕与音频起始误差不超过 200 ms。
- 视频失败能降级为字幕+音频，音频失败能降级为纯字幕。

## 7. 隐私测试

- 应用数据、临时目录、日志、崩溃报告中均不存在 JPEG/PNG/base64 截图。
- 默认请求不发送窗口标题。
- API 密钥不出现在 SQLite、IPC 事件或日志。
- 停止共享后不再产生新帧或请求。
- 一次巡查最多发起两次独立单帧请求，第二次只用于确认高置信度 distracted；任何单次请求不得包含多帧或连续画面。
- 伙伴包无法更改 API 域名、读取截图或执行网络请求。
- 自动巡查每次只写入一条结构化 observation，不再额外生成手工预览记录。

## 8. 端到端验收

端到端验收分成两个互不替代的层次：

### 8.1 加速自动化重放

使用 fake probe、合成帧、内存数据库和本机 mock server，在测试时钟下重放完整会话：

1. 导入并启用 demo 伙伴包。
2. 选择场景、目标、规则和合成屏幕源。
3. 允许应用持续运行，确认 `focused` 且不扣偏航。
4. 禁止应用连续命中 20 秒，确认 `distracted_warning` 和一次偏航。
5. 模拟未知内容与 API 失败，确认 `uncertain_nudge` 且不扣偏航。
6. 模拟恢复 5 分钟，确认 `recovery`。
7. 正常完成并验证评价、历史和伙伴信赖。
8. 扫描临时数据目录，确认不存在巡查截图。

### 8.2 真实 25 分钟人工场

真实场必须让 Electron、Windows 前台探针、用户选择的真实屏幕流、主进程会话服务与 SQLite 连续运行满 25 分钟。它可以使用仅绑定 `127.0.0.1` 的脚本化 mock AI，避免真实外网和真实密钥，但不能使用加速时钟、fake probe 或合成截图代替桌面链路。

人工场至少覆盖：本地允许、本地连续禁止、AI `focused`、默认私人通讯 `uncertain`、明确娱乐内容相隔 15 秒的两帧 `distracted`、停止共享后的安全降级、一次重新授权、暂停/恢复、正常结算、信赖幂等和退出后零残留。具体顺序、记录边界和完成判据见 `docs/11-stage-3-completion-plan.md`。

运行真实场前先执行：

```powershell
pnpm run acceptance:stage3:preflight
```

该预检只运行严格本机 mock 协议、固定节点、一份安全文本文件的全量流式隐私扫描和精确清理，不打开 Electron，也不替代真实场。mock 只接受固定假令牌、固定模型、无窗口标题的请求形状；额外、错位或未消费完的请求均使门禁失败。预检通过后使用 `pnpm run acceptance:stage3` 启动隔离 Electron；启动器等待应用退出，再核对 8 条预期观察、15 秒二次帧、停止/重新授权、暂停/恢复、结算与信赖幂等的低敏轨迹和 SQLite 证据，关闭 mock server，扫描临时 `userData`，最后删除经过路径校验的精确目录。正常退出还必须收到媒体轨停止与 sidecar 退出确认；中断、未满 25 分钟、额外 mock 请求或任一证据不完整均返回失败，不猜测通过。

自动化当前只证明“中断不能通过”、精确 PID 树有有界强制清理兜底、路径校验后的目录清理单元和正常退出回执逻辑；尚未用真实 Electron runner 注入 SIGINT/SIGTERM 来证明中断时的媒体流与进程树清理，因此该项仍由真实场退出检查和 G3-G 复验确认。

## 10. 当前自动化基线

阶段 2A 已把会话调度实现为 Electron 主进程和浏览器预览共用的纯状态机，并覆盖：

- preparing 到 focusing、巡查、反馈、休息及三种终态的合法与非法转换。
- 同种子重放、首次巡查范围、暂停不计时和前两分钟巡查保护。

- 五分钟连续专注触发 recovery，但不恢复偏航额度。
