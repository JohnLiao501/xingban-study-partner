## 3. 下一批实现：隔离验收辅助

先完成 G3-A，再安排真实 25 分钟场。该批次只增加验收基础设施，不改变正式产品判定语义。

### 3.1 隔离用户数据

- 验收启动时使用操作系统临时目录下的独立 `userData`，不读取或写入用户正式 SQLite、设置、历史和信赖。
- 目录名使用随机后缀，启动前解析并验证路径位于系统临时目录内。
- 无论通过、失败或中断，都先停止流、Electron、sidecar 和 mock server，再删除精确的验收目录。
- 不使用删除正式数据库、清空历史或覆盖迁移来实现隔离。

### 3.2 本机脚本化 mock AI

- 只监听 `127.0.0.1` 的随机端口，不访问真实外网，不要求用户真实 API 密钥。
- 按预设序列返回 `focused`、`uncertain`、第一次高置信 `distracted` 和 15 秒后的第二次确认。
- 请求体只在内存中解析和计数，响应后立即释放；不记录 JPEG、base64、目标、窗口标题、Authorization 或模型原始请求。
- 覆盖超时、429、5xx、无效 JSON 和语义矛盾，全部确认安全降级为 `uncertain`。

### 3.3 确定性巡查与摘要

- 只在验收开关下使用固定种子和明确的巡查节点，正式模式继续使用现有随机调度。
- 输出仅包含时间点、状态、标签、原因码、偏航计数、流状态和通过/失败布尔值。
- 摘要不得包含截图、base64、完整目标、完整窗口标题、密钥或模型请求体。
- 自动化先证明取消、超时、中断和清理路径，再允许进入真实 25 分钟场。

## 4. 真实 25 分钟人工场

该场使用原创 demo 伙伴、隔离用户数据和本机 mock AI。用户只需完成一次选源和一次重新授权；Agent 负责启动、观察、计时、结束、进程检查和隐私扫描。下列分钟数均指有效专注计时，暂停耗时不计入 25 分钟，因此实际墙钟时间可以略长于 25 分钟。

建议顺序如下，具体节点由验收提示窗给出，不依赖用户记忆：

1. 0～3 分钟：学习应用命中允许规则，保持 `focused`，不截屏、不调用 AI。
2. 3～5 分钟：禁止规则连续命中至少 20 秒，只记一次本地规则偏航。
3. 5～8 分钟：未知学习页面由 mock AI 返回 `focused`，不扣偏航。
4. 8～11 分钟：默认私人通讯策略返回高置信分心，最终必须是 `uncertain`，不扣偏航。
5. 11～14 分钟：明确娱乐内容连续获得两张相隔至少 15 秒的新帧，只有第二次确认后记一次 AI 偏航。
6. 14～16 分钟：从托盘停止共享；未知内容只能安全降级，不产生迟到处罚。
7. 16～18 分钟：重新授权一次，随后暂停和恢复；暂停时间不计入专注时长。
8. 18～25 分钟：恢复正常学习并完成会话，确认结算、评价、历史和伙伴信赖只写入一次。

通过条件：恰好两次预期偏航，其中一次来自连续本地禁止规则、一次来自 AI 两帧确认；全部 `uncertain` 不处罚；停止共享后无新帧；暂停计时正确；正常结算幂等；退出后 Electron、sidecar、mock server 和捕获流均为 0；临时验收目录删除前扫描无截图/base64，删除后目录不存在。

若应用随机时机、系统弹窗或人为操作使某个场景没有实际发生，本场记录为未完成而不是猜测通过。只补做缺失场景，不重复已取得的内容保护证据。

## 5. Windows 环境矩阵

G3-C～G3-F 分开记录，不能用单次 25 分钟场笼统代替：

| 场景 | 最低检查 |
| --- | --- |
| 全屏应用 | 主窗隐藏/恢复、悬浮窗置顶、所选屏幕源不变、取帧不含应用窗口 |
| 系统停止共享 | 收到 stream ended、AI 取消、会话继续、本地规则仍可用、无迟到处罚 |
| 截图工作窗销毁 | 当前流终止、待确认 AI 取消、其他窗口不获得截图权限、会话安全降级 |
| 休眠/恢复 | 暂停期间不累计时间；恢复后探针和捕获可重建，失败则明确降级 |
| 125%/150% DPI | 主窗/弹窗无裁切，屏幕源与物理显示器一致，768 px 上限仍成立 |
| 多显示器 | 每个 `screen:` source 可识别；选择、拔出副屏和重新授权均安全 |

每个单元记录日期、Windows 版本、显示器数量、缩放、实际结果、残留进程和隐私扫描。没有对应硬件时标记 `blocked-by-environment`，不得标记 `passed`，也不因此重写产品规则。

## 7. 阶段 4 的启动顺序

阶段 3 关闭后，先验证多伙伴公共底座，再生产首个私有伙伴包：

1. 用两份原创伙伴夹具验证伙伴切换、场景、动作降级和关系进度隔离。
2. 在仓库外建立首个私有伙伴的视觉圣经与素材清单。
3. 生产标准关键帧、一个待机循环和十一条状态短片，并逐条执行身份、动作、媒体参数和字幕/TTS QA。
4. 使用公共 Schema 与安装期校验导入；若必须修改通用代码，先证明问题属于协议缺口而不是角色特例。
5. 连续使用一周，记录误判、打扰、媒体重复和信赖节奏，再决定阶段 5 调整项。
